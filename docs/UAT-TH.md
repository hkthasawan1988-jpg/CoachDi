# UAT ก่อน Release

ยังไม่อนุญาต Release จากผล Build หรือ Emulator เพียงอย่างเดียว.
Workflow ต้องผ่าน debug และ android-ui และผู้ตรวจต้องยืนยัน `uat_passed` สำหรับ revision ที่เลือก
หลังตรวจการจอง/ชำระเงินจริงและ Android เครื่องจริงแล้ว. Signing secrets ยังคงเป็นเงื่อนไขแยก.

## เตรียมรายการทดสอบจริง

เจ้าของระบบระบุบัญชีนักกีฬาและโค้ชที่เข้าร่วม วันเวลา สนามที่จองจริง วิธีชำระ และวงเงินสูงสุด.
บันทึกยอดรวม ผู้รับเงิน และเงื่อนไขยกเลิกให้ตรวจสอบก่อนกดยืนยัน.
ผู้ใช้ดำเนินการในแอปธนาคารด้วยตนเอง ไม่ส่งรหัสผ่านหรือ OTP ให้ผู้ทดสอบ.
ใช้สลิปจากธุรกรรมที่เกิดขึ้นจริงเท่านั้น; ไม่สร้างสลิปหรือเปลี่ยนสถานะชำระเงินใน Firebase เพื่อให้ผ่าน.
ประสานการตรวจรับกับโค้ช/ผู้รับเงิน และตกลงการจัดการรายการทดสอบหลังเสร็จสิ้น.
ไม่ลบประวัติหรือธุรกรรมเพื่อทำความสะอาด; ใช้กระบวนการยกเลิก/คืนเงินที่ระบบรองรับเมื่อได้รับอนุมัติ.

## เกณฑ์ผ่าน

| ขั้นตอน | หลักฐานที่ต้องตรวจ |
|---|---|
| Login | Athlete และ Coach เข้าได้ด้วยสิทธิ์จริง; reload/เปิดแอปใหม่ยังได้ session ตามการตั้งค่า |
| เลือก Coach/เวลา/สนาม | ข้อมูลและราคาตรงกัน; เวลาไม่ว่างเลือกไม่ได้; ยืนยันสนามเฉพาะเมื่อจองสนามจริงแล้ว |
| ชำระก่อนจอง | ชื่อผู้รับ/บัญชี/ยอดตรงกับโค้ช; โอนจริง; อัปโหลดสลิปจริงสำเร็จ |
| ส่งคำขอ | มี Booking เพียงรายการเดียว; รายละเอียด/ยอด/สลิป/สถานะถูกต้อง; กดซ้ำไม่สร้างเพิ่ม |
| ฝั่ง Coach | ได้คำขอและตรวจเงินที่เข้าจริงก่อนอนุมัติ; Athlete เห็นสถานะยืนยัน |
| เครือข่ายขัดข้อง | ไม่แสดงชำระสำเร็จเมื่อส่งไม่สำเร็จ; กลับมาดำเนินการต่อได้โดยไม่จองซ้ำ |
| ชำระที่สนาม (ถ้าใช้) | ไม่มีการบังคับแนบสลิป; สถานะค้างชำระที่สนามถูกต้อง; ไม่อ้างว่าจ่ายแล้ว |
| Android เครื่องจริง | ติดตั้ง APK รุ่นที่ตรวจ, login/App Check, เลือกรูปสลิป, keyboard, Back, หมุนจอ, เปิดแอปใหม่ |
| Alert | เนื้อหาเลื่อนได้ ปุ่มรับทราบไม่หลุดจอ ไม่ล้นแนวนอน และไม่มี Booking เกิดจากการรับทราบ |

บันทึก commit/APK checksum, รุ่นเครื่อง/Android/WebView, วันเวลาตรวจ, ผู้ตรวจ และผลผ่าน/ไม่ผ่านรายกรณี.
เก็บเลขธุรกรรม สลิป และข้อมูลบัญชีไว้ในรายงานส่วนตัว ไม่แนบลง public PR หรือ GitHub Actions.

## ขอบเขต Emulator

`NativeUiTest` เปิด packaged app บน Android WebView API 36 จริงใน Emulator:
ตรวจหน้า Login, native mode, targetSdk/permission, Alert ภาษาไทยยาว, การเลื่อน body,
หมุนจอ และปุ่ม Back พร้อม screenshot และ logcat เป็น Actions artifact.
ใช้ข้อมูล Coach จำลองเฉพาะหน้า Alert และไม่ login/ส่ง Booking/ชำระเงินจริง.
ใช้ APK ใน artifact `coach-di-android-ui-<sha>` สำหรับ UAT ต่อ เพราะเป็นไฟล์จาก job ที่รันทดสอบบน Emulator.
จึงไม่ใช่หลักฐานว่า Firebase login, App Check, file picker หรือธุรกรรมจริงผ่านบนเครื่องจริง.

อ้างอิงวิธีรันทดสอบ:
- https://developer.android.com/training/testing/instrumented-tests
- https://github.com/ReactiveCircus/android-emulator-runner
